## **I. STORAGE MEDIA TYPES & CHARACTERISTICS** 💾⚙️

### **MAGNETIC STORAGE (HDD):** 🧲💿
```
PHYSICAL COMPONENTS:
• Platters: Multiple circular disks coated with magnetic material
• Read/Write Heads: Float nanometers above platter surface
• Actuator Arm: Positions heads over correct tracks
• Spindle: Rotates platters at 5,400-15,000 RPM

FORENSIC CHARACTERISTICS:
• Data persists after deletion until overwritten
• Physical damage often recoverable in clean rooms
• Platter imaging possible even with electronic failure
• Slack space contains valuable residual data
```

### **SOLID STATE DRIVES (SSD):** ⚡💾
```
TECHNOLOGY:
• NAND Flash Memory: No moving parts
• Controller: Manages data distribution and wear leveling
• DRAM Cache: Some models include volatile cache

FORENSIC CHALLENGES:
• TRIM Command: Automatically erases deleted data blocks
• Wear Leveling: Data physically moves without OS knowledge
• Garbage Collection: Background data reorganization
• Encryption: Often hardware-based and difficult to bypass
```

[ssd-wearleveling-garbagecollection](./ssd-wearleveling-garbagecollection.md)

### **HYBRID DRIVES (SSHD):** 🔄💿
- **Magnetic platters** for bulk storage
- **SSD cache** for frequently accessed data
- **Forensic considerations** of both technologies

## **II. BOOT PROCESSES ACROSS OS** 🖥️🚀

### **WINDOWS BOOT PROCESS:** ⊞🔄
```
1. POWER-ON SELF-TEST (POST)
   ↓
2. UEFI/BIOS INITIALIZATION
   ↓
3. BOOT MANAGER (bootmgr) LOADS
   ↓
4. WINLOAD.EXE LOADS KERNEL
   ↓
5. NTOSKRNL.EXE INITIALIZES
   ↓
6. SMSS.EXE (Session Manager)
   ↓
7. WINLOGON.EXE & SERVICES
```

**Forensic Artifacts:**
- **BCD (Boot Configuration Data)** - Boot entries and settings
- **Boot Logs** - `C:\Windows\ntbtlog.txt`
- **Prefetch Files** - Boot time program execution evidence

### **LINUX BOOT PROCESS:** 🐧🔄
```
1. BIOS/UEFI INITIALIZATION
   ↓
2. BOOTLOADER (GRUB/LILO)
   ↓
3. KERNEL INITIALIZATION
   ↓
4. INIT PROCESS (systemd/Upstart/SysV)
   ↓
5. RUNLEVEL/TARGET SERVICES
```

**Forensic Artifacts:**
- **Boot Logs** - `/var/log/boot.log`, `dmesg`
- **Initramfs** - Initial RAM filesystem
- **GRUB Configuration** - `/boot/grub/grub.cfg`

### **macOS BOOT PROCESS:** 🍎🔄
```
1. EFI FIRMWARE INITIALIZATION
   ↓
2. BOOT.EFI LOADER
   ↓
3. KERNELCACHE LOADING
   ↓
4. LAUNCHD PROCESS INITIATION
   ↓
5. LOGINWINDOW & USER SESSION
```

**Forensic Artifacts:**
- **EFI Partitions** - Bootloader and drivers
- **System Logs** - `/var/log/system.log`
- **Launch Daemons/Agents** - Startup processes

## **III. FILE SYSTEMS DEEP DIVE** 🗂️🔍

### **WINDOWS FILE SYSTEMS:**

#### **NTFS (NEW TECHNOLOGY FILE SYSTEM):**
```
KEY STRUCTURES:
• $MFT (Master File Table) - Database of all files
• $Bitmap - Track allocated clusters
• $LogFile - Journaling transactions
• $Boot - Boot sector information

FORENSIC ARTIFACTS:
• Alternate Data Streams (ADS) - Hidden data channels
• $MFT Timestamps - Four timestamp types per file
• Cluster Slack - Unused space in allocated clusters
• Journal Analysis - File system transaction history
```

#### **FAT32/exFAT:**
- **Simple structure** - limited forensic artifacts
- **File Allocation Table** - cluster chain mapping
- **Limited timestamps** - basic created/modified times
- **No journaling** - less recovery capability

[fat vs exfat](./fat-exfat.md)
### **LINUX FILE SYSTEMS:**

#### **EXT4 (Fourth Extended File System):**
```
FEATURES:
• Journaling for consistency
• Extents for efficient large file storage
• Improved timestamps (nanosecond precision)

FORENSIC CONSIDERATIONS:
• Deleted inode tracking possible
• Journal analysis for recent activity
• Reserved GDT blocks for forensic recovery
```

#### **XFS, BtrFS, ZFS:**
- **Advanced features** - snapshots, copy-on-write
- **Complex metadata** structures
- **Built-in integrity checking**
- **Scalability** for large storage systems

### **macOS FILE SYSTEMS:**

#### **APFS (Apple File System):**
```
INNOVATIONS:
• Copy-on-Write metadata
• Space Sharing between volumes
• Native encryption support
• Snapshots for Time Machine

FORENSIC CHALLENGES:
• Frequent metadata changes
• Complex space management
• Encryption integration
• Snapshot analysis requirements
```

#### **HFS+ (Legacy):**
- **Catalog file** structure for file tracking
- **Journaling** for data consistency
- **Resource forks** similar to ADS

> [fat-ntfs-ext4-apfs](./fat-ntfs-ext4-apfs.md)

## **V. ENTERPRISE STORAGE SYSTEMS** 🏢💾

### **RAID (REDUNDANT ARRAY OF INDEPENDENT DISKS):**
```
COMMON LEVELS:
• RAID 0: Striping (performance, no redundancy)
• RAID 1: Mirroring (duplicate data)
• RAID 5: Striping with parity (balance of performance/redundancy)
• RAID 6: Double parity (higher fault tolerance)
• RAID 10: Mirroring + Striping (high performance & redundancy)

FORENSIC CONSIDERATIONS:
• All members required for reconstruction
• Controller configuration critical
• Order of drives matters in some configurations
• Hardware vs. software RAID differences
```

### **NAS (NETWORK ATTACHED STORAGE):** 🌐💽
- **File-level access** over network protocols
- **Multiple file systems** often in single device
- **Proprietary implementations** by vendors (Synology, QNAP)
- **Log analysis** for access patterns and timestamps

### **SAN (STORAGE AREA NETWORK):** 🌐🔗
- **Block-level access** over dedicated networks
- **Fibre Channel or iSCSI** protocols
- **Complex multi-path configurations**
- **Snapshot and replication features**

[raid-nas-san](./raid-nas-san.md)
