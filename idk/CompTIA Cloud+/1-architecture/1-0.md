#### **1.1 Cloud Service Models**
**Vibe:** *Choosing your level of control—from raw infrastructure to pure experience.*

| Keyword                         | Concept & Vibe                                                                                              |
| :------------------------------ | :---------------------------------------------------------------------------------------------------------- |
| **IaaS**                        | Rent virtualized hardware (servers, storage). You manage OS + apps.<br>*You build on their foundation.* 🏗️ |
| **PaaS**                        | Rent a platform for building/app hosting. They manage runtime.<br>*You code, they handle the stage.* 🎭     |
| **SaaS**                        | Rent a full software app. No management needed.<br>*You use the magic.* 🧙‍♂️                               |
| **FaaS**                        | Run code in response to events. No server management.<br>*Code that sparks + vanishes.* ⚡                   |
| **Shared Responsibility Model** | You secure your data + apps; they secure the cloud.<br>*A partnership, not a free ride.* 🤝                 |

#### **1.2 Service Availability**
**Vibe:** *Designing for failure—because it’s not *if*, but *when*.*

| Keyword                     | Concept & Vibe                                                                                            |
| :-------------------------- | :-------------------------------------------------------------------------------------------------------- |
| **Region**                  | Geographic area with multiple data centers.<br>*Your cloud’s continent.* 🌍                               |
| **Availability Zone (AZ)**  | Isolated location within a region for fault tolerance.<br>*Your cloud’s fortified city.* 🏙️              |
| **Cloud Bursting**          | Temporarily using cloud resources during traffic spikes.<br>*Scaling into the cloud during peak vibe.* 📈 |
| **Edge Computing**          | Process data near its source, not in a central cloud.<br>*Think local, act global.* ⚡                     |
| **Availability Monitoring** | Continuously checking if resources are up and responsive.<br>*The cloud's pulse check.* 💓                |
| **RTO**                     | Max acceptable downtime after a failure.<br>*How fast you must recover.* ⏱️                               |
| **RPO**                     | Max acceptable data loss measured in time.<br>*How much history you can lose.* 🕰️                        |
| **Hot Site**                | Fully redundant site ready for immediate failover.<br>*Always ready, always live.* 🔥                     |
| **Warm Site**               | Partially equipped backup—requires some setup.<br>*Almost there, just need coffee.* ☕                     |
| **Cold Site**               | Backup location with power/cooling, no hardware.<br>*Starting from scratch when things go cold.* ❄️       |
| **Multicloud Tenancy**      | Using multiple cloud providers to avoid lock-in.<br>*Don’t put all your eggs in one cloud.* 🥚☁️          |

#### **1.3 Cloud Networking**
**Vibe:** *Weaving secure, smart connections—the nervous system of the cloud.*

| Keyword                       | Concept & Vibe                                                                                          |
| :---------------------------- | :------------------------------------------------------------------------------------------------------ |
| **VPN**                       | Secure, encrypted tunnel over a public network.<br>*Your private subway under the city.* 🚇🛡️          |
| **Dedicated Connections**     | Private, direct link to the cloud provider.<br>*Your VIP highway, no traffic.* 🛣️⚡                     |
| **Application Load Balancer** | Distributes traffic based on content (HTTP/HTTPS).<br>*The smart bouncer for web apps.* 🎩⚖️            |
| **Network Load Balancer**     | Handles high-volume, low-level traffic.<br>*The traffic cop for raw speed.* 🚦📡                        |
| **Application Gateway**       | Cloud-native web traffic manager.<br>*The router with a purpose.* 🧭🔀                                  |
| **CDN**                       | Caches content at edge locations for fast delivery.<br>*Global instant replay for your data.* 🌍⚡       |
| **Firewalls**                 | Filters traffic based on security rules.<br>*The digital guard at the gate.* 🛡️🔥                      |
| **VPC**                       | Isolated virtual network within the cloud.<br>*Your private castle in the sky.* 🏰☁️                    |
| **Peering**                   | Direct connection between two VPCs.<br>*Secret tunnel between castles.* 🕵️‍♂️🔗                        |
| **Transit Gateway**           | Hub for connecting multiple VPCs.<br>*Grand Central Station for your networks.* 🚉🧠                    |
| **Subnets**                   | Segmented network within a VPC.<br>*Rooms in your cloud castle.* 🚪🏠                                   |
| **Routing and Switching**     | Directing traffic within and between networks.<br>*The city's road and street signs.* 🛣️🧭             |
| **VLAN**                      | Logical separation of a physical network.<br>*Creating neighborhoods on one street.* 🏘️                |
| **SDN**                       | Networking controlled by software, not hardware.<br>*Networking through code, not cables.* 🤖🔧         |
| **BGP**                       | Protocol that routes traffic between autonomous systems.<br>*The internet’s postal service.* 📮🌐       |
| **Static Routes**             | Manually defined network paths.<br>*“Take this road, every time.”* 🗺️⛔                                 |
| **Route Tables**              | Set of rules that determine where network traffic is directed.<br>*The map your traffic follows.* 🗺️🧭 |

#### **1.4 Storage Resources & Technologies**
**Vibe:** *Where you put your digital stuff—balancing speed, cost, and access.*

| Keyword                      | Concept & Vibe                                                                                                |
| :--------------------------- | :------------------------------------------------------------------------------------------------------------ |
| **Tiered Storage: Hot**      | For frequently accessed data. High cost, low latency.<br>*Your quick-access drawer.* 🗄️⚡                     |
| **Tiered Storage: Warm**     | For less frequently accessed data. Moderate cost and latency.<br>*Your closet of things you kinda need.* 🧥📦 |
| **Tiered Storage: Cold**     | For rarely accessed data. Low cost, high latency.<br>*Your attic archive.* ❄️📦                               |
| **Tiered Storage: Archive**  | For long-term retention. Very low cost, very high latency.<br>*Deep storage—hope you never need it.* 🗃️⏳     |
| **SSD**                      | Fast, durable flash storage. Ideal for performance.<br>*The sports car of storage.* 🚗💨                      |
| **HDD**                      | Slower, magnetic storage. Ideal for capacity.<br>*The reliable minivan.* 🚐📀                                 |
| **Object Storage**           | Stores data as objects (e.g., images, videos).<br>*Infinite digital closet.* 🧥📦                             |
| **Block Storage**            | Raw storage volumes for file systems or databases.<br>*Blank canvas for data.* 🎨🔲                           |
| **File Storage**             | Shared file systems (e.g., NFS, SMB).<br>*Shared network drive.* 👥📂                                         |
| **Performance Implications** | How storage choice affects speed and responsiveness.<br>*Don’t use a scooter on the highway.* 🛴⚡             |
| **Cost Implications**        | How storage choice impacts your bill.<br>*Premium features, premium price.* 💸🎩                              |

#### **1.5 Cloud-Native Design Concepts**
**Vibe:** *Building for the cloud—agile, resilient, and smart.*

| Keyword                             | Concept & Vibe                                                                                                    |
| :---------------------------------- | :---------------------------------------------------------------------------------------------------------------- |
| **Cloud-Provided Managed Services** | Pre-built services offered by the cloud provider (e.g., databases, AI).<br>*Don’t build what you can rent.* 🛠️☁️ |
| **Microservices**                   | Small, independent services communicating via APIs.<br>*Do one thing, do it well.* 🧩🔗                           |
| **Loosely Coupled Architecture**    | Services operate independently without tight dependencies.<br>*Stay together, not tangled.* 🕸️🙅‍♂️              |
| **Fan-out**                         | Distributing tasks to multiple workers for parallel processing.<br>*Divide and conquer.* ⚡🤜🤛                    |
| **Service Discovery**               | Services automatically find and communicate with each other.<br>*Networking without name tags.* 🏷️🔍             |

#### **1.6 Containerization Concepts**
**Vibe:** *Code in a box—consistent, portable, and isolated.*

| Keyword | Concept & Vibe |
| :--- | :--- |
| **Stand-alone** | A container that runs independently without orchestration.<br>*The lone wolf container.* 🐺📦 |

| **Image Registries** | Repositories for storing and managing container images.<br>*The library of container blueprints.* 📚🐳 |

#### **1.7 Virtualization Concepts**
**Vibe:** *The OG abstraction—one physical machine, many virtual ones.*

| Keyword | Concept & Vibe |
| :--- | :--- |
| **Stand-alone** | A VM that operates independently.<br>*The classic workhorse.* 💻🔲 |
| **Clustering** | Group of hosts working as a single system for high availability.<br>*Strength in numbers.* 🤝🔗 |
| **Cloning** | Creating an identical copy of a VM.<br>*Digital twin.* 👯‍♂️ |
| **Host Affinity** | Rules to keep VMs on the same host for performance.<br>*Keeping friends close.* 👫🔗 |
| **Hardware Pass-through** | Giving a VM direct access to physical hardware.<br>*Bypassing the abstraction for speed.* ⚡🔧 |
| **Network Types: Overlay Networks** | Virtual networks built on top of physical networks.<br>*Networks on networks.* 🕸️🔗 |
| **Network Types: VM Networks** | Virtual networks connecting VMs.<br>*The social network for virtual machines.* 💻🌐 |
| **Storage: Local** | Storage attached directly to the host.<br>*The VM’s personal hard drive.* 💾🏠 |
| **Storage: SAN** | High-speed network providing block-level storage to multiple hosts.<br>*Shared storage for high performers.* 🚀💾 |
| **Storage: NAS** | Network-attached storage providing file-level access.<br>*The shared family drive.* 👥📂 |
